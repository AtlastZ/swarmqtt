swarmqtt

Unleash a swarm of IoT devices on your MQTT / MQTTS broker (powered by emqtt-bench).

Broker

Broker on this machine: use host.docker.internal

Ramp & latency (optional)

Runs each step in turn and stops at the first one with more connect failures than this, or under 99% connected. Steps run in the order written and may repeat, e.g. 100000, 100000 runs 100k twice and reconnects everything in between. Replaces Concurrent devices and Stop after.

Measures delivered msg/s and publish-to-receive latency (publish mode). Adds an 8-byte binary timestamp to the front of every payload.

TLS / Certificates

Verify applies to Test connection only. emqtt-bench does not verify the server certificate during the load test.

Load

A device that fails to connect tries again this many times before it counts as failed.

Stop after 0 min 0 s = run until you press Stop

Each worker container holds back publishing until it has started every client connection, then all its connected clients publish at the same moment (workers and machines are not synchronised with each other).

%i = device number, %c = client ID

Sent as-is instead of random bytes. Variables: %TIMESTAMP% %TIMESTAMPMS% %UNIQUE% (unique number, not sequential) %RANDOM% (Payload bytes of random data) %RANGE:<min>:<max>% (new random value in range on every message) %WALK:<min>:<max>:<step>% (random walk, own value per device, moves a random amount of at most step per message). Decimals follow the most precise number written (40:60 integers, 20.0:30.0 one decimal); typos are refused. Empty = random bytes of Payload size.
